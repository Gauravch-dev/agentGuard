# Runbook

## Persistent local configuration

Use a private trusted directory outside the capsule for the database and secrets.
Generate separate random owner/runtime/integrity secrets (32+ characters) in your
secret manager and set `AG_OWNER_TOKEN`, `AG_RUNTIME_TOKEN`, `AG_INTEGRITY_KEY` in the
trusted service environment. Never mount the application environment into a capsule.
Do not change the integrity key for an existing database without a migration plan.
Do not put real employee data in this prototype. Only the built-in synthetic fixture
is supported.

`uv run uvicorn application.api:create_app --factory --host 127.0.0.1 --port 8000`

No defaults or usable credentials are provided. Missing, repeated or placeholder
secrets reject startup. Owner and privileged runtime credentials cannot ingest
sensor evidence; sensors cannot create/approve tasks. No CORS, environment proxies,
external provider or public bind is enabled. The owner credential represents one
synthetic reviewed Finance owner; production multi-user RBAC/SSO is pending.

Loopback HTTP is for a single trusted host. Do not expose it on a LAN. A remote
Member 2 exporter needs an authenticated local relay or separately reviewed mTLS
transport. Reverse-proxy trust and public deployment are outside this prototype.

## Member 2 integration

Read `contracts/broker_protocol.md` and `application/runtime_adapter.py`. Implement
a trusted adapter and pass it to `create_app(settings, runtime)` from a trusted
composition module. Default `UnavailableRuntime` always refuses launch. Effective
required controls: network_none, restricted_filesystem, no_new_privileges,
resource_limits, sensor_ready, peer_verified. This application checks the report
from the adapter; it cannot independently prove Linux controls on Windows.

Create a protected sensor registry JSON file and set `AG_SENSOR_REGISTRY` to it:

```json
{"collector-01":{"token":"GENERATE_A_DISTINCT_RANDOM_SECRET_AT_DEPLOYMENT","host_id":"linux-host-01","sources":["host_sensor","network_sensor","sensor_health"]}}
```

A separate registered policy-engine identity is needed for enforcement verdicts.
The registry is operator configuration, never an API payload. Each identity is
restricted to its configured host and sources. Missing cgroup/start observations
are retained but reconciled as Unverified; a wrong capsule/host mapping is rejected.
Exporter sends source events to `POST /internal/v1/events`; coverage intervals to
`POST /internal/v1/coverage`; trusted runtime sends completion after process exit.
See schemas and tests/contract for exact envelopes. Use synchronized UTC clocks;
source timestamps are never repaired. Receipt time is generated by the server.

Run the Unix socket server as a separately protected trusted broker process.
Member 2 supplies the peer resolver and starts `serve_socket` in a private
per-capsule directory. Package only `agent_demo/finance_agent.py` into the capsule;
never package `application/synthetic.py`, the database, integrity secrets, sensor
credentials or local model configuration. No Docker image/platform implementation
is included, preserving Member 2 ownership.

## Optional real local model

Install Ollama and the reviewed `qwen2.5:7b` model separately on the trusted host,
listening only on 127.0.0.1:11434. Set `AG_LOCAL_MODEL_ENABLED=true` on the trusted
broker service. The client uses fixed `/api/chat`, no proxies or redirects, no
provider keys, schema-constrained JSON tool choices, bounded replies and a timeout.
Only canonical verified aggregates plus one controlled lab document reach it.
The model runtime must already contain the model; the application never downloads
one or forwards data externally. Default remains disabled.

Run `python -m agent_demo.finance_agent --socket <capsule-mounted-socket>` inside a
verified capsule. `--document injected` selects the controlled malicious lab text.
If the real model refuses the injection, report that outcome. The adversarial test
driver demonstrates application denial only and never counts as a model attack.
Record real model/runtime version and evidence after performing this joint run.

## Storage and recovery

SQLite WAL is used for a single-worker prototype, with an immutable contract table
and a shared append-only evidence ledger. Ledger kinds separate bindings, broker
receipts, events, coverage, findings, results, readiness and review notes. This
replaces the proposed dedicated tables with one sequenced ledger for atomicity;
PostgreSQL roles/migrations remain pending. HMAC chains detect row changes when the
key is protected, but do not defeat a host administrator, whole-database rollback,
key theft, truncation without an external checkpoint or source dishonesty. Protect
files with OS ACLs and back up database plus key separately. No deletion/export API.
Results verify ledger integrity before presenting trusted assessments.

Failures: inspect readiness/evidence in dashboard. Launch refusal is not proof of
capsule termination. Termination stays running/unverified until independent runtime
inspection confirms no descendants. Failed model calls emit unknown effect and do
not fabricate reports. Restart/new revision uses fresh capsule/channel identities;
finished versions cannot authorize broker access. Broker writes are serialized and
receipts/report release are committed together. A process crash during a local
model call has no external business write; retry may perform that model computation
again. One application worker only; distributed replay control is pending.
