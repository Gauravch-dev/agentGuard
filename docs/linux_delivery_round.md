## Changes delivered

- `agentguard/prebirth.py` starts process and expanded file/socket subscriptions
  before `docker start`. Real root-only executable and successful openat canaries
  must traverse the sensor before startup proceeds. UID must be explicitly integer
  zero; missing, boolean or conflicting identity is refused. The exact witness
  records are fsynced into private host evidence before readiness is acknowledged.
  Only the target container's subsequent records enter its source journals.
- The runtime invokes this before-start hook while retaining its original signed
  contract, monotonic/wall deadline, watchdog and containment rules. A failed hook
  prevents bootstrap startup and requests cleanup. Captured subscriptions continue
  through registration; there is no close/reopen handoff between these streams.
- Observation hooks now include VFS scalar/vector I/O, file permission/mmap checks
  and actual UDP/IPv6 UDP/TCP send functions, alongside the prior syscall hooks.
  Probe-specific synthetic file paths distinguish inherited-FD and readv evidence
  from unrelated interpreter startup. Real curl connect evidence is recorded.
- A permission check is an attempt, not proof of reading mapped pages. Zero-byte
  I/O is not a completed data effect. A positive socket send is not packet delivery.
  Unknown socket destinations remain absent. Signed kernel return sizes and IP
  family/address combinations are validated by the unchanged host-event bridge.
- `agentguard/source_time.py` compares original source timestamps at nanosecond
  precision before Python datetime truncation. Sub-microsecond reversals remain
  gaps. No timestamp repair, tolerance or replacement event class was introduced.
- `agentguard/policy_control.py` validates exact managed policy names and private
  files, then serializes host policy mutations using a root-private Linux lease.
  This addresses a real concurrent-load timeout. Acquisition and loading remain
  bounded; the original task deadline is not extended.
- Durable export yields between bounded batches. Recovery keeps retrying finished
  workers' immutable journals/queues without requiring a service restart. Each
  pass handles at most 64 journals and scans at most 4,096 retained manifests;
  a larger history is explicitly flagged for investigation. It never re-admits an
  old workload or restores an old channel. Pending evidence is retained.
- The current owner posture, paging, revision notes, historical views and cleanup
  APIs were exercised against actual observers. The dashboard now says
  **Cleanup verified** after verified interrupted/completed cleanup.
- Linux startup no longer prints the owner credential into application stdout/logs;
  the operator retrieves it from the existing root-private control state.

Shared schemas, signed task permissions, source authentication, broker envelope,
report checks and mandatory admission/coverage/conflict gates are preserved.

## Mandatory blockers

1. Process/file/socket subscriptions now precede startup, but the independent
   AF_PACKET tap still attaches after birth. Initial runtime/namespace attribution
   gaps and unknown loss also prevent certifying the whole initial interval.
2. Mmap page access, denied seccomp attempts and other unsupported mechanisms do
   not gain complete coverage merely because listed hooks loaded or probes passed.
3. Namespace packet metadata does not identify the originating process. A genuine
   kernel packet/process/cgroup identity join still needs implementation and review.
4. Consistent source-clock export and measured end-to-end loss/export accounting
   remain unresolved. Missing metric families stay unknown. More counters are now
   sampled, including cache-fetch and handler failures; they do not fill absent ones.

These are implementation/verification blockers, not a missing Docker/Linux
installation. The full admitted Finance report, final positive security demo and
full matrix remain blocked until these requirements actually pass.

## Reproduce and operate

Use the existing approved rootful Linux environment and immutable image IDs from
the [version manifest](linux/version_manifest.json). Start the managed sensor and
local model using [the existing runbook](linux_supervisor_round.md#reproduce-and-operate).
Run one control plane on port 8000. It remains loopback-only; credentials/evidence
stay in root-private host state outside capsules. The optional collector flag is
not an approval override. Stop with Ctrl+C; preserve evidence when cleanup is uncertain.

From the repository root, with the existing Linux virtual environment active:

```sh
finance_image=$(docker image inspect --format '{{.Id}}' agentguard-finance:round2)
probe_image=$(docker image inspect --format '{{.Id}}' agentguard-probes:delivery)
model_digest=$(python -c 'import json; print(json.load(open("platform/versions.json"))["approved_model_digest"])')
python -m scripts.linux_scope_lab --image-id "$probe_image" --output docs/linux/scope_final_review.json
python -m scripts.linux_delivery_lab --image-id "$finance_image" --approved-model-digest "$model_digest" --output docs/linux/delivery_final_review.json
python -m scripts.linux_continuous_lab --image-id "$finance_image" --approved-model-digest "$model_digest" --output docs/linux/continuous_delivery_review.json
python -m scripts.linux_baseline_lab --image-id "$probe_image" --iterations 3
python -m scripts.linux_source_audit
python -m scripts.linux_probe_image_audit --image-id "$probe_image"
python -m scripts.integration_validate_round --label linux
```

Run live experiments sequentially so shared sensor setup and timing measurements
are controlled. A failed positive experiment returns nonzero and is retained.
